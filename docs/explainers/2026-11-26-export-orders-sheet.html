GECO ORDER DASHBOARD · EXPORT

One order, one row

Excel exports now open on an Orders sheet with one row per order. The existing product-level detail remains on the second sheet, Lines.

What GECO saw

The earlier workbook repeated an order number for each product line. GECO read those repeated numbers as duplicate orders, even though the rows represented products within the same order.

What changed

Orders shows the customer, tier, status, PO, number of product lines, stored order total and creation time. An order with no lines shows zero items. Lines keeps the previous columns and rows. CSV exports retain their existing format.

Proof

A workbook written and read back with exceljs contained Orders, Lines in that order. Four fixture orders produced four Orders rows and seven Lines rows, including the existing placeholder for an order without lines.

Items were 4, 1, 0 and 1; stored totals were 111.23, 42.50, 9.99 and 73.10. The fixture CSV matched the output from origin/main byte for byte.

A negative run supplied line rows to Orders and failed the row-count assertion: seven rows instead of four.
